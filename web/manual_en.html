Purpose and access

Can-Hub 1.0.1 collects measurements from manually configured CAN devices, checks data freshness and exposes them to an HMI over Modbus TCP. The web interface and local LCD provide diagnostics. Open http://IP-ADDRESS/can. The omen web account is separate from the RPi system account. On first use, set a password of 10–128 characters and a mandatory IPv4 address. Select the correct network prefix and enter a gateway and DNS if required. Choose an unused address. PL/EN flag buttons change the language; the browser remembers your choice. Save forms before switching languages. Login sessions last up to 8 hours. Logging out ends the session.

01 Status

NET indicates Ethernet link status, not Internet access. A green Modbus indicator means a client has sent valid read requests within the last 5 seconds; a diagnostic client also qualifies, so this does not identify a specific HMI. CPU load and temperature refer to the Raspberry Pi. The application alarm starts at 80°C and does not change fan control. The module list shows current states. RX/TX and error counters cover the lifetime of each interface. A present CAN0/CAN1 interface does not prove reception. An active simulator is clearly marked as test mode.

02 Modules — protocol v3

Select a unique node ID (1–95) and physical channel CAN0/CAN1. Enter names and Modbus addresses manually. Measurements receive permanent positions 1–24; CAN identifiers and slots are automatic. Positions must match the ESP32 firmware. Deleting a row never shifts or reuses its position. Disabling preserves the position. Existing v1/v2 nodes retain their mapping.

Fixed type: signed int16, −32768…32767, little-endian. Multiplier 1–1000 is applied by HUB; overflow produces zero and bits 0+12. Data, status and age addresses are independent, zero-based, range 100–65535. Each occupies one register; blank disables that mapping. Modbus TCP port 502, Unit ID 1, FC03. Interpret measurements as signed int16 and status as uint16.

The switch takes effect after Save configuration. A disabled signal has value 0, age 0 and status 4 only (bit 2). It raises no sensor alarm; module connectivity remains monitored independently. Re-enabling waits for a new complete measurement/status pair. Age 65535 means no available measurement; other values are seconds capped at 65534.

Modbus TCP and HMI communication loss

HMI reads HUB IP, TCP port 502, Unit ID 1, FC03. Measurement addresses remain unchanged. System registers: 0 interface version (2), 1 HUB life counter, 2–3 uptime, 4 module count, 5 faulty module count. HMI must monitor replies and an advancing life counter and indicate HUB OFFLINE locally. HUB cannot deliver a new status to a disconnected HMI. V2 status registers require bit tests, not legacy quality codes.

03 Settings — network and account

Change the IP address together with prefix, gateway and DNS. The gateway must be in the same subnet. Gateway and DNS may be empty on an isolated local network. Saving changes the Ethernet profile; the current session stays at the old IP until restart or network reconnection. Wait for a successful save message, then use Restart RPi. After restart, open http://NEW-IP/can and update the device address in the HMI and SSH/PuTTY settings. The application validates address syntax but cannot guarantee that an address is unused. Incorrect settings may require recovery from a local console. Password changes require the current password and invalidate other sessions. After shutdown, the RPi needs power/hardware-button action to start again; the website cannot start a powered-off computer.

Backup and restore

JSON backup uses format can-hub-config, schema version 3. It includes module protocol:3, next_position and signal position with derived can_id/slot, enabled, names, IDs, channels, timeouts, multipliers, independent register addresses and remote backup settings. Endianness, type and error-mask fields are not configurable for v2. Heartbeat ID is derived again from module ID.

Select a file up to 1 MB and choose merge missing items or replace all. Preview makes no changes; applying activates settings without restarting Raspberry Pi. Merge identifies modules by channel+ID and v3 signals by permanent position (v2 by frame+slot), preserving existing switches and addresses. Different protocols cannot be merged within one module. Conflicting registers, frame pairs and slots are rejected. The previous configuration remains downloadable.

Version 1/2 backups can be restored in compatibility mode without silently changing firmware or addresses. Legacy modules retain their old status codes and require compatible ESP32 firmware. Backups exclude the web password, firmware, history and system IP settings. SFTP remains configuration-only; upload is not enabled.

05 Simulator

The link opens /sym. The simulator uses a separate vcanhub and Modbus server at 127.0.0.1:1502; it does not transmit on physical CAN or replace data served on TCP502. You can stop a module, simulate a sensor fault, stop test-HMI reads and override NET/temperature indicators. The automatic test takes about20 s. LCD preview shows the program framebuffer, not a photograph. Simulated states do not change real temperature or cooling. Stop the simulator after testing. Its simplified status codes (0 waiting,1 OK,2 no data,3 sensor fault) differ from the physical status table below.

06 Manual and 07 Info

The manual is read from a separate HTML file in the selected language and can be printed from the browser. Info shows the logo, version, author and links. Close it using Close, the cross or Esc. External links and the buycoffee graphic require Internet access; CAN/Modbus operation is local and does not require Internet access.

V2 status bit fields — HMI

The status register is no longer an enum 0–12: several bits may be set together. A healthy reading normally has status 0; disabled has status 4. Bits 0, 1, 3 or 4 suppress data. Disabled bit 2 takes precedence. HUB passes detail bits 5–15 through without interpretation; firmware sets bit 0 when the reading must not be used. Only HUB sets bits 1–4. Multiplier overflow adds bits 0+12.

Existing 12-state HMI indicators and macros must be adapted. Do not use old code 11 as HUB OFFLINE in this register: HMI must detect loss of HUB locally and display it separately. When communication fails, sensor detail bits may describe the last received sample rather than a new diagnosis.

Frame format v3

Data ID = 16 × NODE_ID + 2 × group (0–7); status ID = data ID + 1. Heartbeat ID = 0x700 + NODE_ID. All 16 IDs of a node block are reserved. Position = 3 × group + slot + 1; slot 0–2. Fixed signed int16, little-endian. Byte 0 = 3; byte 1 = matching sample sequence; bytes 2–3, 4–5 and 6–7 hold values or uint16 statuses. Unused fields are zero. Sequence advances even for unchanged measurements. Heartbeat has an independent counter, flags in bytes 2–3 and uptime in 4–7; sent every second independently of sensor errors. Repeated counters do not refresh the watchdog.

Greenhouse ID 3: 0x30/31 S1–S3; 0x32/33 S4, AM2302 temperature/humidity; 0x34/35 Analog 1–3; 0x36/37 Analog 4–6; 0x38/39 Analog 7–8 and spare. Group 7, 0x3E/3F, positions 22–23: cycle count and DS count at startup. 12 frames every 2.5 s plus heartbeat 0x703 every second. Modbus addresses and HMI interpretation are unchanged. ADS cannot detect a disconnected analog probe on its own.

04 CAN frame monitor

Select a module and a parameter or All module parameters. Passive view; no CAN transmissions. Shows raw bits, IDs, DLC, version, sequence, RX counts and reception/sequence ages. Status 0 green, 1 red; data light blue; headers/heartbeat dark yellow. Raw status bits 1–4 are reserved for HUB and grey. Unconfigured positions still show raw bits: zeroes alone do not prove a field is unused. Description explains every status bit. Stale frames are labelled. The lower section separately shows the effective Modbus status including HUB flags.

LCD supply voltage

The CPU row displays the Raspberry 5 V supply measured by PMIC EXT5V_V. Missing readings display --, never core voltage or an assumed 5 V.

Sampling — FTP archive and charts

“05 Sampling” downloads data from a device providing FTP. This optional feature depends on the device and its configuration: trends, events, operation logs and recipe/EM files may be available.

  1. Enter a local LAN IP, FTP username and password. Current HMI: 192.0.2.10, username uploadhis. Password is stored on the RPi with restricted file permissions and is never returned by the API. An empty field preserves it.
  2. Select categories and manual mode or an interval of 1, 2, 3, 4, 5, 7, 14 or 30 days. Saving sets the next run after the interval. RPi must remain on; the browser may be closed. An overdue job runs after service startup.
  3. “Log in / download” saves the form and starts a background download. Progress and errors appear below. Only one download can run at a time.
  4. Select a dataset and 1 to 8 signals. Use 1/7/30/365-day windows, dates, arrows or slider. Time is the panel wall clock as recorded, without a timezone shift. Lines show interval means; bands show minimum/maximum. CSV exports this displayed view.
  5. DTL does not include all HMI scaling. Use display units and scaling. Confirmed defaults: SHT31/BMP280 temperature ×0.1 °C, SHT31 humidity ×0.1 % RH, BMP280 pressure ×0.1 hPa. Other scales require verification. Originals never change.
  6. Archive keeps originals and previous changed versions. Filter for e.g. em0. Download retrieves the original; Versions lists previous copies. Empty categories mean no exposed files, not a verified full register backup.

The DTL variant used by this panel was validated against EasyConverter for 22 datasets. Unsupported or damaged files remain archived but are excluded from charts. Structural validation cannot prove physical measurement correctness. A file changing during transfer must be downloaded again.

Safety limits: 64 MiB per file, 512 MiB per run, 256 MiB free-space reserve. No automatic deletion. Archive and separate settings: /var/lib/can-hub-web/sampling. Standard module configuration JSON export does not include the archive or FTP password. Use FTP on a trusted LAN. Restore, deletion and writing to the HMI are not implemented.

Quality summary counts structurally valid, damaged, incomplete, suspicious, unsupported and unchecked files separately. Changing transfers are retried up to three times; structurally suspicious downloads are read again once. Recovery means a new valid transfer, never guessed or interpolated values. Damaged originals remain in the archive, excluded from charts; previous versions are retained. SHA256 identifies archived bytes; no manufacturer checksum is available to prove original measurement correctness.

Select files in the archive and choose Download selected (ZIP) to download their current originals and a manifest to the computer (up to 128 MiB per package). Individual downloads and previous versions remain available. Delete selected from RPi requires confirmation, removes all local versions and corresponding chart samples, and compacts the index to reclaim space. This does not delete from HMI; subsequent scheduled downloads may archive the same files again. Download a copy to your computer first if needed. FTP archive is separate from the module configuration JSON backup.

Forgotten password — administrator reset

No reinstallation or configuration reset is required. The omen web account password is stored as a scrypt hash and cannot be retrieved. Administrator access to the Raspberry Pi through SSH or a local terminal is required; the web password is separate from the operating system password.

  1. Open an interactive terminal on the Raspberry Pi, locally or through SSH.
  2. Run sudo can-hub-reset-password.
  3. Select 1 to enter your own password twice (10–128 characters), or 2 to generate a random password. Typed passwords are hidden. Alternatively run sudo can-hub-reset-password --generate. The terminal prompts are in Polish.
  4. Type RESET to confirm. Any other answer cancels. Save the generated password in a password manager; it is displayed before saving and is never written to the journal.
  5. After the success message, log in at /can as omen using the new password.

The reset briefly stops the web service, CAN reception and Modbus. The HMI may briefly indicate that the HUB is unavailable. All previous web sessions expire. No Raspberry Pi reboot is required. Modules, Modbus addresses, IP, archives and other settings are preserved. Do not manually delete account.json: this would reopen initial setup.

If an error occurs after confirmation, the password may already have been saved. Check sudo systemctl status can-hub-web.service and, if necessary, run sudo systemctl start can-hub-web.service. A missing account file aborts the reset. An interactive terminal is required; passwords are not accepted as command-line arguments.
