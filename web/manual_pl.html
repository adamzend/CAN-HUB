Przeznaczenie i dostęp

Can-Hub 1.0.1 zbiera pomiary z ręcznie skonfigurowanych urządzeń CAN, ocenia ich aktualność i udostępnia dane panelowi HMI przez Modbus TCP. WWW i lokalny LCD służą do diagnostyki. Otwórz http://ADRES-IP/can. Konto WWW omen jest niezależne od konta systemowego RPi. Przy pierwszym uruchomieniu ustaw hasło 10–128 znaków oraz obowiązkowy adres IPv4. Ustaw poprawny prefiks, a bramę i DNS podaj, jeśli są potrzebne. Wybieraj adres wolny w sieci. Język PL/EN zmienisz przyciskami z flagami; wybór pamięta przeglądarka. Przed zmianą języka zapisz formularze. Sesja logowania trwa do 8 godzin. Wylogowanie kończy sesję.

01 Status

NET oznacza stan połączenia Ethernet, nie potwierdza dostępu do Internetu. Zielona kontrolka Modbus oznacza poprawne zapytania klienta w ostatnich 5 sekundach; klientem może być także narzędzie diagnostyczne, więc nie jest to identyfikacja konkretnego HMI. CPU i temperatura dotyczą Raspberry. Alarm aplikacji zaczyna się od 80°C; nie zmienia sterowania wentylatorem. Lista modułów prezentuje bieżące stany. Liczniki RX/TX i błędów obejmują czas od utworzenia interfejsu. Sama obecność CAN0/CAN1 nie potwierdza odbioru ramek. Aktywny symulator jest wyraźnie oznaczony jako tryb testowy.

02 Moduły — protokół v3

Nowy moduł wymaga unikalnego ID 1–95 i wyboru fizycznej magistrali CAN0/CAN1. Nazwy i adresy Modbus wpisujesz ręcznie. Dodawane pomiary dostają trwałe pozycje 1–24. ID ramek i sloty są wyliczane automatycznie; nie można ich zmienić. Pozycje muszą odpowiadać programowi ESP32. Usunięcie wiersza nie przesuwa pozostałych ani nie odzyskuje jego numeru. Wyłączenie suwakiem zachowuje pozycję. Numeracji nie wolno zmieniać w istniejącym firmware bez zgodnej zmiany konfiguracji. Starsze moduły v1/v2 zachowują dotychczasowe mapowanie.

Typ jest stały: int16, zakres −32768…32767, little-endian. Mnożnik 1–1000 działa w HUB-ie; przepełnienie daje zero i bity 0+12. Adresy danych, statusu i wieku są niezależne, liczone od zera, z zakresu 100–65535. Każdy zajmuje jeden rejestr, puste pole wyłącza jego udostępnianie. Odczyt przez Modbus TCP, port 502, Unit ID 1, FC03. Rejestr pomiaru interpretuj jako signed int16, statusu jako uint16.

Przełącznik działa po Zapisz konfigurację. Wyłączony pomiar ma wartość 0, wiek 0 i wyłącznie status 4 (bit 2). Nie powoduje alarmu czujnika, ale stan łączności całego modułu jest nadal widoczny. Po ponownym włączeniu HUB czeka na nowy kompletny zestaw danych i statusów. Wiek 65535 oznacza brak dostępnego pomiaru; pozostałe wartości są sekundami, ograniczonymi do 65534.

Modbus TCP i utrata łączności HMI

HMI odczytuje dane z IP HUB-a, portu 502, Unit ID 1, FC03. Adresy pomiarów pozostają niezmienione. Rejestry systemowe: 0 wersja interfejsu (2), 1 licznik życia HUB-a, 2–3 czas pracy, 4 liczba modułów, 5 liczba modułów z problemem. HMI powinno kontrolować odpowiedzi oraz zmianę licznika życia i lokalnie oznaczać BRAK HUB. Po utracie Ethernet HUB nie może przesłać nowego statusu do odłączonego HMI. Rejestry statusu v2 wymagają testowania bitów, a nie starych kodów jakości.

03 Ustawienia — sieć i konto

Adres IP zmieniasz wraz z prefiksem, bramą i DNS. Brama musi należeć do tej samej podsieci. Brama i DNS mogą być puste dla izolowanej sieci lokalnej. Zapis zmienia profil Ethernet; bieżąca sesja pozostaje pod starym IP do restartu lub ponownego zestawienia połączenia sieciowego. Poczekaj na komunikat o udanym zapisie, następnie użyj Restart RPi. Po restarcie otwórz http://NOWE-IP/can i zmień adres urządzenia w HMI oraz ustawienia połączeń SSH/PuTTY. Program sprawdza format adresów, ale nie gwarantuje, że adres jest wolny. Błędne ustawienia mogą wymagać poprawy z lokalnej konsoli. Zmiana hasła wymaga dotychczasowego hasła; pozostałe sesje są unieważniane. Wyłączenie RPi wymaga ponownego włączenia zasilania/przycisku sprzętowego; WWW nie uruchomi wyłączonego komputera.

Backup i przywracanie

Backup JSON ma format can-hub-config i wersję struktury 3. Zawiera protocol:3 i next_position w module, position w sygnale oraz wyliczone can_id/slot, enabled, nazwy, ID, kanały, timeouty, mnożniki, niezależne adresy rejestrów i ustawienia serwera backupu. Parametry endian, typ i maska błędów nie są konfigurowane dla v2/v3/v3. Heartbeat jest wyliczany ponownie z ID modułu.

Wybierz plik do 1 MB i tryb: uzupełnij brakujące albo zastąp wszystko. Podgląd niczego nie zmienia; zatwierdzenie aktywuje ustawienia bez restartu RPi. Uzupełnianie rozpoznaje moduł po kanale+ID, sygnał v3 po trwałej pozycji (v2 po ramce+slocie). Zachowuje istniejące suwaki i adresy. Nie wolno scalać różnych protokołów w jednym module. Kolizje rejestrów, par ramek i pozycji są odrzucane. Kopia poprzedniej konfiguracji pozostaje do pobrania.

Backup v1/v2 można odtworzyć w trybie zgodności, bez automatycznej zmiany firmware i adresów. Moduły v1 zachowują dawny format statusów; przywracaj je wyłącznie ze zgodnym programem ESP32. Backup nie zawiera hasła WWW, firmware, historii ani ustawień IP systemu. SFTP pozostaje konfiguracją przygotowaną na przyszłość — przycisk wysyłki nie jest aktywny.

05 Symulator

Link otwiera /sym. Symulator korzysta z osobnego vcanhub i Modbus 127.0.0.1:1502; nie nadaje na fizyczny CAN i nie zastępuje danych serwera TCP502. Pozwala zatrzymać moduł, zasymulować błąd czujnika, zatrzymać odczyty testowego HMI i podmienić wskazania NET/temperatury. Test automatyczny trwa około20 s. Podgląd LCD pokazuje bufor programu, nie zdjęcie ekranu. Symulowane stany nie zmieniają rzeczywistej temperatury ani chłodzenia. Zatrzymaj symulator po testach. Jego uproszczone statusy (0 oczekiwanie,1 OK,2 brak danych,3 błąd czujnika) różnią się od tabeli statusów fizycznych poniżej.

06 Instrukcja i 07 Info

Instrukcja jest odczytywana z osobnego pliku HTML w wybranym języku i może być wydrukowana z przeglądarki. Info pokazuje logo, wersję, autora i linki. Zamknij okno przyciskiem Zamknij, krzyżykiem lub Esc. Linki zewnętrzne i grafika buycoffee wymagają dostępu do Internetu; praca CAN/Modbus jest lokalna i nie wymaga Internetu.

Statusy bitowe v2/v3/v3 — HMI

Rejestr statusu nie jest dawnym kodem 0–12. To pole bitowe: wiele bitów może wystąpić równocześnie. Prawidłowy pomiar zwykle ma status 0, wyłączony status 4. Dane są zerowane dla bitów 0, 1, 3 lub 4. Dla wyłączenia bit 2 ma pierwszeństwo. Szczegóły 5–15 są przekazywane bez interpretacji przez HUB; firmware ustawia bit 0, gdy odczytu nie wolno użyć. Bity 1–4 ustawia wyłącznie HUB. Przy przepełnieniu mnożnika HUB dodaje bity 0+12.

Dotychczasowe kontrolki 12-stanowe i makra HMI wymagają dostosowania do bitów. Nie używaj dawnego kodu 11 jako BRAK HUB w tym rejestrze: brak samego HUB-a HMI wykrywa lokalnie i przedstawia oddzielnie. Przy braku komunikacji szczegóły czujnika mogą pochodzić z ostatniego odebranego zestawu i nie oznaczają nowej diagnozy.

Format ramek v3

ID danych = 16 × NODE_ID + 2 × grupa (grupy 0–7), ID statusu = ID danych + 1. Heartbeat = 0x700 + NODE_ID. Każdy moduł rezerwuje wszystkie 16 ID swojego bloku. Pozycja pomiaru = 3 × grupa + slot + 1, slot 0–2. Typ int16 ze znakiem i little-endian są stałe. Bajt 0 = 3, bajt 1 = licznik zestawu 0–255; bajty 2–3, 4–5 i 6–7 to pomiary lub odpowiadające im pola statusu uint16. Nieużywane pola są zerowe. Licznik zestawu zwiększa się także dla niezmiennych pomiarów. Heartbeat ma własny licznik, diagnostykę w bajtach 2–3 i uptime w 4–7; wysyłany co sekundę niezależnie od błędów czujników. Brak zmiany sekwencji nie odświeża watchdog-a.

Szklarnia ID 3: 0x30/31 S1–S3; 0x32/33 S4, AM2302 temperatura i wilgotność; 0x34/35 Analog 1–3; 0x36/37 Analog 4–6; 0x38/39 Analog 7–8 i rezerwa. Grupa 7: 0x3E/3F, pozycje 22–23: licznik cykli i liczba DS przy starcie. Nadal 12 ramek co 2,5 s oraz heartbeat 0x703 co sekundę. Nie zmieniono rejestrów Modbus ani interpretacji HMI. ADS nie wykrywa sam odłączenia sondy analogowej.

04 Monitor ramek CAN

Wybierz moduł i pojedynczy parametr lub Wszystkie parametry modułu. Monitor jest pasywny: niczego nie wysyła na CAN. Pokazuje surowe bajty i bity, ID dziesiętne i szesnastkowe, DLC, wersję, sekwencję, liczbę odbiorów oraz wiek ramki i zmiany sekwencji. Status: 0 zielony, 1 czerwony; dane jasnoniebieskie; nagłówki i heartbeat ciemnożółte. Bity 1–4 statusu surowego są zarezerwowane dla HUB-a i szare. Pozycje nieskonfigurowane nadal pokazują surowe bity: same zera nie dowodzą, że pole jest nieużywane. Okno Opis objaśnia wszystkie bity. Nieaktualne ramki są oznaczone; dolna sekcja pokazuje odrębnie efektywny status Modbus z bitami HUB-a.

Napięcie na LCD

Obok CPU widoczne jest zasilanie Raspberry 5 V odczytane z EXT5V_V układu PMIC. Brak odczytu jest oznaczony --; nie jest zastępowany napięciem rdzenia ani stałą wartością 5 V.

Próbkowanie — archiwum FTP i wykresy

W menu „05 Próbkowanie” można pobierać dane z urządzenia udostępniającego FTP. Funkcja jest opcjonalna; dostępność trendów, zdarzeń, rejestru operacji oraz receptur/EM zależy od urządzenia i jego konfiguracji.

  1. Wprowadź adres IP w sieci lokalnej, użytkownika oraz hasło FTP. Dla obecnego panelu: 192.0.2.10, użytkownik uploadhis. Hasło jest przechowywane na RPi z ograniczonym dostępem, nigdy nie jest zwracane przez API. Puste pole zachowuje hasło.
  2. Wybierz kategorie i tryb: ręcznie albo co 1, 2, 3, 4, 5, 7, 14 lub 30 dni. Zapis ustawia następny termin po wybranym okresie. RPi musi działać; strona nie musi pozostawać otwarta. Po przerwie w zasilaniu zaległe pobranie zostanie uruchomione po starcie usługi.
  3. „Zaloguj / pobierz” zapisuje formularz i rozpoczyna pobieranie w tle. Postęp i ewentualne błędy pojawiają się pod formularzem. Drugi proces nie może wystartować równocześnie.
  4. Wybierz zestaw trendów i od 1 do 8 sygnałów. Zakres 1/7/30/365 dni, daty, strzałki i suwak pozwalają przeglądać historię. Czas jest lokalnym czasem zapisanym przez panel, bez dodatkowego przesunięcia strefy. Linia pokazuje średnią w przedziale, pasmo minimum i maksimum; CSV eksportuje dokładnie taki widok.
  5. DTL nie opisuje wszystkich skal HMI. W „Jednostki i skala” ustaw mnożnik oraz jednostkę. Ustawiono potwierdzone skale: SHT31 i BMP280 temperatura ×0,1 °C, SHT31 wilgotność ×0,1 % RH, ciśnienie BMP280 ×0,1 hPa. Inne skale wymagają potwierdzenia. Skala nie zmienia źródła.
  6. Archiwum przechowuje oryginały i poprzednie zmienione wersje. Filtr pozwala znaleźć np. em0. „Pobierz” zwraca oryginalny plik, „Wersje” wcześniejsze kopie. Brak plików w kategorii oznacza brak dostępnych plików, nie potwierdzenie pełnej kopii wszystkich rejestrów.

Obsługiwany parser DTL: wariant używany przez obecny panel, zweryfikowany z EasyConverterem dla 22 zestawów. Nieobsługiwane lub uszkodzone pliki pozostają w archiwum, ale nie są pokazywane jako poprawne pomiary. Kontrola struktury nie dowodzi poprawności fizycznego pomiaru. Plik zmieniający się podczas transferu wymaga ponownego pobrania.

Limity ochronne: 64 MiB na plik, 512 MiB na przebieg, rezerwa 256 MiB wolnej pamięci. Kopie nie są automatycznie kasowane. Archiwum i osobne ustawienia znajdują się w /var/lib/can-hub-web/sampling. Standardowy eksport konfiguracji modułów JSON nie zawiera tego archiwum ani hasła FTP. FTP jest przeznaczone do zaufanej sieci lokalnej. Nie zaimplementowano przywracania, usuwania ani zapisu plików na panelu.

Podsumowanie jakości oddzielnie zlicza pliki o poprawnej strukturze, uszkodzone, niekompletne, podejrzane, nieobsługiwane i bez analizy zawartości. Zmienny transfer jest ponawiany do trzech prób; podejrzany strukturalnie plik jest pobierany ponownie raz. Odzyskanie oznacza nowy poprawny transfer, nigdy zgadywanie lub interpolację wartości. Błędny oryginał pozostaje w archiwum, bez wykresu; wcześniejsze wersje są zachowane. SHA256 identyfikuje zapisane bajty; brak sumy kontrolnej producenta pozwalającej udowodnić poprawność oryginalnego pomiaru.

Zaznacz pliki w archiwum i wybierz „Pobierz zaznaczone (ZIP)”, aby zapisać aktualne oryginały wraz ze spisem plików na komputerze (do 128 MiB na paczkę). Dostępne pozostaje pobieranie pojedynczych plików i wcześniejszych wersji. „Usuń zaznaczone z RPi” wymaga potwierdzenia, usuwa wszystkie lokalne wersje plików i ich punkty wykresów oraz porządkuje indeks, odzyskując miejsce. Nie usuwa danych z HMI; następne pobranie może zarchiwizować je ponownie. W razie potrzeby najpierw pobierz kopię na komputer. Archiwum FTP jest oddzielne od backupu JSON konfiguracji modułów.

Zapomniane hasło — reset administracyjny

Nie wymaga reinstalacji ani zmiany konfiguracji. Hasło konta WWW omen jest zapisane jako skrót scrypt i nie można go odczytać. Potrzebny jest dostęp administracyjny do Raspberry Pi przez SSH lub lokalny terminal; hasło WWW nie jest hasłem systemowym.

  1. Otwórz interaktywny terminal na RPi (przez SSH lub lokalnie).
  2. Uruchom sudo can-hub-reset-password.
  3. Wybierz 1, aby wpisać własne hasło dwukrotnie (10–128 znaków), lub 2, aby wygenerować losowe hasło. Wpisywane hasło nie jest widoczne. Możesz też użyć sudo can-hub-reset-password --generate.
  4. Wpisz RESET, aby zatwierdzić. Inna odpowiedź anuluje operację. Wygenerowane hasło zapisz w menedżerze haseł; pojawi się w terminalu przed zapisem, nie jest zapisywane w dzienniku.
  5. Po komunikacie powodzenia zaloguj się do /can jako omen z nowym hasłem.

Reset krótko zatrzymuje usługę WWW, odbiór CAN i Modbus. HMI może chwilowo pokazać brak HUB-a. Wszystkie wcześniejsze sesje WWW wygasają. Nie jest wymagany restart RPi; moduły, adresy Modbus, IP, archiwa i pozostałe ustawienia nie zmieniają się. Nie usuwaj ręcznie account.json — spowodowałoby to powrót do pierwszej konfiguracji.

Jeśli pojawi się błąd po zatwierdzeniu, hasło mogło już zostać zapisane. Sprawdź sudo systemctl status can-hub-web.service i w razie potrzeby uruchom sudo systemctl start can-hub-web.service. Brak pliku konta przerywa reset. Narzędzie wymaga interaktywnego terminala i nie przyjmuje hasła w argumentach polecenia.
